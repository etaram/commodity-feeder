# Develop business for a represented client
Read references/operating-contract.md and references/development.md.

1. Resolve client/workspace ownership and allowed claims. Use native PPTX/PDF/DOCX extraction before OCR/vision; bound permitted website crawling.
2. Build an editable dossier with product capabilities, limitations, cases, markets, business role and claim-level slide/page/URL provenance. Mark client statements as such.
3. Confirm a usable dossier and propose distinct ICPs for end users, EPCs, integrators and distributors. Do not make up prospect companies.
4. For RO, match feedwater/salinity, capacity/unit, output quality, pretreatment, recovery, energy, installation/service footprint and concentrate responsibilities.
5. Retrieve real prospects from authorized existing datasets first, then permitted sources/connectors. Separate structural fit, evidenced need and explicit current buying signal.
6. Resolve entity/domain/contact attribution, duplicates, prior relationships and conflicts. Keep private client data separate.
7. Prepare a bounded pilot plan, reviewed account list, value proposition, drafts, cadence, owner, budget, stop rules and success metrics.
8. Create RFQ/outreach drafts using assets/outreach.md. Drafting is not sending. Use existing supported mail integration only under explicit scoped campaign authorization.
9. Recheck reply, bounce, opt-out, pause, recipient, template and attachment scope before every scheduled message. Route meaningful replies to an owner.
10. Treat LinkedIn as optional: use permitted supported integration or human task queue; do not assume account creation enables automation.
11. Convert qualified needs to the existing opportunity/deal model, preserving evidence and context.

Apollo/Clay may be useful optional adapters if genuinely connected and permitted. Tool availability, entitlements and enrichment costs must be inspected in the host runtime; these skills do not grant API access or credits.
